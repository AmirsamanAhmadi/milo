# Gmail and Outlook sync

Each member can connect Gmail and Outlook under Settings → Email sync. Sign-in uses authorization-code OAuth with PKCE, a short-lived single-use state bound to the signed-in member, and encrypted access/refresh tokens. Tokens never appear in browser API responses. Disconnect removes the local connection and imported previews; users can also revoke access in Google or Microsoft account settings.

Members can configure their own connection directly in the UI without editing `.env`: open **Settings → Email sync**, choose **Create connection**, follow the provider setup links, copy the displayed redirect URL, then enter the OAuth client ID and secret and select **Save connection**. Select **Sign in with Gmail/Outlook** to authorize the mailbox, then **Sync now**. Personal client secrets are encrypted, never returned to the browser, and isolated by member. Leave the secret field blank when editing to keep an existing secret. Changing client details disconnects the mailbox and removes imported previews so a fresh authorization is required. **Remove my app configuration** restores the workspace connection if one exists.

OAuth applications still need registration with Google or Microsoft; the portal cannot issue those providers' client credentials. The UI links to their registration pages and setup guides. Administrators can optionally provide shared workspace clients through environment settings:

- Google: enable Gmail API, configure the consent screen and test users, create a Web application client. Set `GMAIL_CLIENT_ID` and `GMAIL_CLIENT_SECRET` in `.env`. Register `http://localhost:8080/api/email/callback/gmail` as the redirect URI (replace origin for a hosted instance). Requested scope is `https://www.googleapis.com/auth/gmail.readonly`. Google may require verification for public use of this restricted scope.
- Microsoft: register a Web application supporting organizational and personal Microsoft accounts. Add delegated `Mail.Read` access, create a client secret, and set `OUTLOOK_CLIENT_ID` and `OUTLOOK_CLIENT_SECRET`. Register `http://localhost:8080/api/email/callback/outlook`. The flow also requests `offline_access` for refresh tokens.

UI connection settings take effect immediately. Environment changes require `docker compose up --build -d`. Sign in through the provider and select **Sync now**. Gmail scans up to 50 recruitment-related messages from the last 90 days; Outlook checks the latest 50 messages and retains recruitment-related previews. Repeated syncs deduplicate by provider/message ID. This is a bounded manual sync, not a complete mailbox archive or background subscription. Multiple simultaneous syncs of the same mailbox are prevented. A company match is a suggestion; stages are not automatically changed.

No message sending, deletion, attachments or AI email processing occurs. Stored previews are private to the signed-in member. Never commit client secrets, OAuth tokens or mailbox contents.

References: [Google web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [Microsoft authorization-code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow), [Microsoft message listing](https://learn.microsoft.com/en-us/graph/api/user-list-messages?view=graph-rest-1.0).
